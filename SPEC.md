# ТЗ: Telegram-бот запису на послуги (демо + основа для клієнтів)

## 1. Мета

Бот запису для сервісного бізнесу (барбершоп, салон, масаж, автомийка). Перша версія — демо для вигаданого барбершопу, яке показуємо потенційним клієнтам. Код пишемо так, щоб під нового клієнта змінювались лише налаштування й дані, а не логіка.

## 2. Стек

- Python 3.12, aiogram 3.x
- SQLAlchemy 2.x (async) + aiosqlite, міграції через Alembic (пізніше перехід на PostgreSQL без зміни коду)
- APScheduler для нагадувань
- pydantic-settings для `.env`, YAML для налаштувань бізнесу
- pytest + pytest-asyncio для тестів
- Docker + docker-compose для деплою

## 3. Налаштування бізнесу (все, що відрізняється між клієнтами)

Файл `config/business.yaml`:

- назва, адреса, телефон, посилання на карту, Instagram
- часовий пояс (за замовчуванням `Europe/Kyiv`)
- крок слотів (15 хв)
- горизонт запису (14 днів наперед)
- мінімальний час до запису (60 хв від поточного моменту)
- дедлайн скасування/перенесення клієнтом (2 год до візиту)
- увімкнені нагадування (24 год і 2 год)

Усі тексти бота — в `bot/texts.py` (одне місце для ребрендингу). Мова інтерфейсу — українська.

`.env`: `BOT_TOKEN`, `ADMIN_IDS` (список Telegram ID власників), `DEMO_MODE` (true/false), `DATABASE_URL`.

## 4. Моделі даних

- **Service**: id, name, duration_min, price, is_active
- **Master**: id, name, is_active, telegram_id (необов'язково, щоб майстер теж отримував сповіщення)
- **MasterService**: зв'язок майстрів і послуг (не кожен майстер робить усі послуги)
- **WorkingHours**: master_id, weekday (0–6), start_time, end_time, break_start, break_end (перерва необов'язкова)
- **TimeOff**: master_id, start_dt, end_dt, reason — відпустки, лікарняні, ручне блокування часу
- **Client**: id, telegram_id, name, phone, created_at
- **Booking**: id, client_id, master_id, service_id, start_dt, end_dt, status (`confirmed` / `cancelled_by_client` / `cancelled_by_admin` / `completed` / `no_show`), created_at, reminded_24h, reminded_2h

Усі datetime зберігаємо в UTC, показуємо в часовому поясі бізнесу.

## 5. Розрахунок вільних слотів (`services/slots.py`)

Найважливіша частина, покривається тестами в першу чергу.

Для майстра, дати й послуги:
1. Беремо робочі години майстра на цей день тижня. Немає — день вихідний.
2. Віднімаємо перерву, TimeOff і підтверджені записи.
3. Кандидати на початок — кожні `slot_step` хвилин від початку робочого дня.
4. Слот валідний, якщо `start + duration` повністю вміщується у вільний проміжок.
5. Відкидаємо слоти раніше ніж `зараз + мінімальний час до запису`.

Варіант «будь-який майстер»: об'єднання слотів усіх майстрів, які роблять цю послугу. При виборі часу призначаємо майстра з найменшою кількістю записів у цей день.

Захист від подвійного запису: при підтвердженні повторно перевіряємо доступність слоту в межах однієї транзакції. Якщо слот уже зайнятий — повідомляємо клієнта і показуємо інші слоти.

Обов'язкові тест-кейси: вихідний день; перерва посередині дня; послуга не влазить перед кінцем дня; перетин з існуючим записом; TimeOff на частину дня; мінімальний час до запису; «будь-який майстер»; зміна дати через північ у часовому поясі Києва.

## 6. Сценарій клієнта

`/start` → привітання з назвою бізнесу і меню: **Записатися**, **Мої записи**, **Контакти**.

Запис:
1. Вибір послуги (назва, тривалість, ціна).
2. Вибір майстра або «Будь-який».
3. Вибір дати: найближчі 14 днів, показуємо лише дні з вільними слотами.
4. Вибір часу (inline-кнопки).
5. Номер телефону — запитуємо один раз через кнопку «Поділитися контактом», потім пам'ятаємо.
6. Екран підтвердження з усіма деталями → **Підтвердити** / **Назад**.
7. Повідомлення про успішний запис.

Мої записи: майбутні записи з кнопками **Скасувати** і **Перенести** (доступні, якщо до візиту більше за дедлайн скасування; інакше показуємо телефон бізнесу).

Кнопка **Назад** на кожному кроці. Усі сценарії через FSM aiogram.

## 7. Сповіщення

- Власнику (всім `ADMIN_IDS`) і майстру (якщо вказаний `telegram_id`): новий запис, скасування, перенесення.
- Клієнту: підтвердження запису; скасування з боку адміністратора.

## 8. Нагадування

Задача APScheduler щохвилини шукає записи, яким потрібне нагадування за 24 год або 2 год, надсилає і ставить прапорець `reminded_*`. Так нагадування не губляться після перезапуску бота. Записи, створені менше ніж за 2 год до візиту, нагадування не отримують.

## 9. Адмінка (`/admin`, лише для `ADMIN_IDS`)

- **Сьогодні** / **Тиждень** — список записів по майстрах.
- **Послуги** — додати, змінити, приховати.
- **Майстри** — додати, змінити, приховати, прив'язати послуги.
- **Графік** — робочі години по днях тижня для кожного майстра.
- **Блокування часу** — створити TimeOff.
- **Скасувати запис** — зі сповіщенням клієнту.
- **Позначити** запис як `completed` або `no_show`.

## 10. Демо-режим (`DEMO_MODE=true`)

- Тестові дані: «Demo Barber», 3 майстри, 5 послуг (стрижка, стрижка бороди, комплекс, дитяча стрижка, камуфлювання сивини), графік Пн–Сб 10:00–20:00 з перервою 14:00–15:00, кілька вже зайнятих слотів, щоб календар виглядав реалістично.
- У меню кнопка **«Подивитись як власник»**: будь-хто бачить адмінку з демо-даними, щоб потенційний клієнт зрозумів обидві сторони.
- Щоночі о 04:00 дані скидаються до початкового стану.
- Запис у демо працює повністю, включно з нагадуваннями.

## 12. Етапи і критерії готовності

1. **Каркас**: структура, конфіг, `/start` відповідає. Бот запускається локально і в Docker.
2. **БД**: моделі, міграції, seed демо-даних. `python -m seed.demo_data` заповнює базу.
3. **Слоти**: `slots.py` + усі тест-кейси з розділу 5 проходять.
4. **Запис**: повний сценарій клієнта від послуги до підтвердження.
5. **Мої записи**: перегляд, скасування, перенесення з урахуванням дедлайну.
6. **Сповіщення й адмінка**: усі пункти розділів 7 і 9.
7. **Нагадування**: працюють і не дублюються після перезапуску.
8. **Демо-режим**: усе з розділу 10.
9. **Деплой**: README з інструкцією розгортання на VPS через docker-compose.

Після кожного етапу: тести проходять, зміни закомічені з описом етапу.
