# Telegram-бот запису на послуги

Бот запису для сервісного бізнесу: барбершопу, салону, масажу, автомийки. Клієнт обирає послугу, майстра, дату й час. Власник отримує сповіщення й керує записами, послугами, майстрами та графіком прямо в Telegram (`/admin`). Клієнтам приходять нагадування за добу й за 2 години до візиту.

Під нового клієнта змінюються лише налаштування й тексти, логіка лишається тією самою (див. [«Новий клієнт»](#новий-клієнт)).

## Можливості

- **Запис**: послуга → майстер або «будь-який» → дата → час (згруповано на ранок, день і вечір) → телефон → підтвердження. Захист від подвійного запису на той самий час.
- **Мої записи**: перегляд, скасування й перенесення не пізніше ніж за 2 години до візиту.
- **Нагадування** за 24 і за 2 години з кнопками «Буду ✅» і «Скасувати». Після перезапуску бота не дублюються.
- **Сповіщення** власнику й майстру: новий запис, скасування, перенесення.
- **Адмінка** `/admin`: записи на сьогодні й тиждень, позначки «відбувся» / «не прийшов», скасування зі сповіщенням клієнту, послуги, майстри, графік, блокування часу.
- **Демо-режим**: кнопка «Подивитись як власник», тестові дані, щоночі о 04:00 усе скидається.
- **Надійність**: незавершений запис переживає перезапуск бота (стан зберігається в базі), щоденний бекап бази зі зберіганням 7 копій.

## Налаштування

Усе, що відрізняється між клієнтами, лежить у трьох місцях:

| Файл | Що там |
|---|---|
| `.env` | секрети й режим роботи (див. таблицю нижче) |
| `config/business.yaml` | назва, адреса, телефон, карта, Instagram, часовий пояс, правила запису, нагадування |
| `bot/texts.py` | усі тексти бота |

Змінні в `.env` (зразок — `.env.example`):

| Змінна | Що означає |
|---|---|
| `BOT_TOKEN` | токен бота від [@BotFather](https://t.me/BotFather) |
| `ADMIN_IDS` | Telegram ID власників через кому, наприклад `111111111,222222222` |
| `DEMO_MODE` | `true` — демо з тестовими даними, `false` — робочий бот клієнта |
| `DATABASE_URL` | база даних; за замовчуванням `sqlite+aiosqlite:///data/bot.db` |
| `BACKUP_DIR`, `BACKUP_KEEP` | папка для бекапів і скільки останніх копій зберігати (за замовчуванням `data/backups`, 7) |
| `LOG_FILE` | файл логу; потрібен на Windows, у Docker лишайте порожнім |

Свій Telegram ID можна дізнатися, написавши боту [@userinfobot](https://t.me/userinfobot).

> ⚠️ Файл `.env` містить токен — нікому його не пересилайте й не додавайте в git (він уже в `.gitignore`).

## Запуск на Windows

Нижче описано, як запустити бота на ноутбуці з Windows 10/11 так, щоб:

- він сам стартував після ввімкнення чи перезавантаження Windows (зокрема після оновлень), навіть без входу в обліковий запис;
- працював у фоні без вікон PowerShell;
- сам перезапускався, якщо впав.

Як це влаштовано: Планувальник завдань Windows під час старту системи запускає скрипт `scripts\run_bot.ps1`. Скрипт оновлює базу й запускає бота, а якщо бот зупиняється з будь-якої причини, через 15 секунд запускає його знову. Логи пишуться в папку `logs`.

> Назви пунктів меню Windows подано українською, а в дужках — англійською. Залежно від версії Windows переклад може трохи відрізнятися.

### Крок 1. Встановіть Python 3.12

1. Відкрийте <https://www.python.org/downloads/windows/> і завантажте **Windows installer (64-bit)** для останньої версії **Python 3.12**.
2. Запустіть інсталятор. **На першому екрані обов'язково поставте галочку «Add python.exe to PATH»**, потім натисніть «Install Now».
3. Перевірте, що Python встановився. Натисніть `Win`, введіть `PowerShell`, відкрийте його і виконайте:

   ```powershell
   py -3.12 --version
   ```

   Має з'явитися `Python 3.12.x`.

### Крок 2. Завантажте код бота

1. Відкрийте сторінку репозиторію на GitHub → зелена кнопка **Code** → **Download ZIP**.
2. Розпакуйте архів у **`C:\demo-bot`**, так щоб файл `README.md` лежав одразу в `C:\demo-bot`, а не у вкладеній папці.

   Шлях краще без пробілів і кирилиці: деякі програми з такими шляхами працюють погано.

### Крок 3. Встановіть залежності

У PowerShell виконайте по черзі:

```powershell
cd C:\demo-bot
```

Переходимо в папку бота. Усі наступні команди виконуються з неї.

```powershell
py -3.12 -m venv .venv
```

Створюємо «віртуальне середовище» — окрему папку `.venv`, куди встановляться бібліотеки бота. Вони не змішаються з іншими програмами на ноутбуці.

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Встановлюємо бібліотеки бота. Займає 1–2 хвилини.

### Крок 4. Створіть файл `.env`

```powershell
copy .env.example .env
notepad .env
```

Перша команда створює `.env` із зразка, друга відкриває його в Блокноті. Заповніть:

- `BOT_TOKEN=` — токен від @BotFather;
- `ADMIN_IDS=` — ваш Telegram ID (дізнатися: @userinfobot);
- `DEMO_MODE=true` — для демо;
- `LOG_FILE=logs/bot.log`.

Збережіть файл (`Ctrl+S`) і закрийте Блокнот.

### Крок 5. Підготуйте базу й перевірте запуск

```powershell
.\.venv\Scripts\python.exe -m alembic upgrade head
```

Створюємо файл бази `data\bot.db` з усіма таблицями.

```powershell
.\.venv\Scripts\python.exe -m bot.main
```

Пробний запуск. У демо-режимі бот сам заповнить порожню базу тестовими даними. Відкрийте свого бота в Telegram і надішліть `/start` — має прийти привітання з меню.

Зупиніть бота в PowerShell клавішами `Ctrl+C`.

### Крок 6. Перевірте скрипт автозапуску

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File C:\demo-bot\scripts\run_bot.ps1
```

Це той самий запуск, який потім робитиме Планувальник. Перевірте `/start` у Telegram. Відкрийте `C:\demo-bot\logs\bot.log` — там має бути рядок `Запуск бота`.

Зупиніть клавішами `Ctrl+C`.

### Крок 7. Створіть завдання в Планувальнику

1. Натисніть `Win + R`, введіть `taskschd.msc` і натисніть Enter — відкриється **Планувальник завдань (Task Scheduler)**.
2. Праворуч натисніть **«Створити завдання…» (Create Task…)**. Саме цей пункт, а не «Створити просте завдання» — у простому немає потрібних налаштувань.

**Вкладка «Загальні» (General):**

3. **Ім'я (Name)**: `Demo Barber бот`.
4. Оберіть **«Виконувати незалежно від входу користувача» (Run whether user is logged on or not)**. Саме це дозволяє боту стартувати одразу після ввімкнення ноутбука, без входу в Windows, і працювати без вікна.
5. Внизу в **«Налаштувати для» (Configure for)** оберіть свою версію Windows 10/11.

**Вкладка «Тригери» (Triggers):**

6. Натисніть **«Створити…» (New…)**.
7. **«Почати завдання» (Begin the task)**: **«Під час запуску» (At startup)**.
8. Поставте галочку **«Відкласти завдання на» (Delay task for)** і оберіть **1 хвилина**: так Windows встигне підключитися до інтернету.
9. Натисніть **OK**.

**Вкладка «Дії» (Actions):**

10. Натисніть **«Створити…» (New…)**, дія — **«Запуск програми» (Start a program)**.
11. **Програма або сценарій (Program/script)**:

    ```
    powershell.exe
    ```

12. **Додати аргументи (Add arguments)**:

    ```
    -NoProfile -ExecutionPolicy Bypass -File "C:\demo-bot\scripts\run_bot.ps1"
    ```

    `-ExecutionPolicy Bypass` дозволяє запустити саме цей скрипт, не змінюючи налаштувань безпеки Windows для інших.

13. **Робоча папка (Start in)**:

    ```
    C:\demo-bot
    ```

14. Натисніть **OK**.

**Вкладка «Умови» (Conditions):**

15. **Зніміть** галочку **«Запускати лише від мережі живлення» (Start the task only if the computer is on AC power)**. Інакше бот не запуститься, коли ноутбук на батареї.

**Вкладка «Параметри» (Settings):**

16. Залиште **«Дозволити запуск завдання на вимогу» (Allow task to be run on demand)** — щоб можна було запускати вручну.
17. Поставте **«Якщо завдання не виконано, перезапускати кожні» (If the task fails, restart every)**: **1 хвилина**, **«Кількість спроб перезапуску» (Attempt to restart up to)**: **999**. Це запасний варіант на випадок, якщо сам скрипт не стартує. Падіння бота скрипт обробляє сам.
18. **Обов'язково зніміть** галочку **«Зупиняти завдання, якщо воно виконується довше ніж» (Stop the task if it runs longer than)** — інакше Windows вимкне бота через 3 дні.
19. **«Якщо завдання вже виконується» (If the task is already running)**: **«Не запускати новий екземпляр» (Do not start a new instance)**.
20. Натисніть **OK**. Windows попросить **пароль від облікового запису**: він потрібен, щоб запускати завдання без входу в систему. Потрібен саме пароль, а не PIN-код. Якщо ви входите тільки за PIN-кодом, введіть пароль від облікового запису Microsoft.

### Крок 8. Запустіть і перевірте

1. У списку завдань знайдіть `Demo Barber бот`, натисніть правою кнопкою → **«Виконати» (Run)**.
2. Зачекайте 10–20 секунд і надішліть боту `/start` у Telegram.
3. Перезавантажте ноутбук і, **не входячи в Windows**, перевірте бота в Telegram з телефону — має відповідати приблизно через 1–2 хвилини після ввімкнення.

### Крок 9. Не давайте ноутбуку засинати

Поки ноутбук спить, бот не працює. Нагадування, які мали прийти в цей час, прийдуть одразу після пробудження, якщо вони ще актуальні.

1. **Параметри → Система → Живлення (й акумулятор) → Екран і сон** (Settings → System → Power → Screen and sleep): для **«Від мережі» (When plugged in)** встановіть **«Ніколи» (Never)** для сну.
2. Щоб бот працював із закритою кришкою: **Панель керування → Електроживлення → «Дія під час закриття кришки»** (Control Panel → Power Options → Choose what closing the lid does), для **«Від мережі»** оберіть **«Нічого не робити» (Do nothing)**.

### Як зупинити або оновити бота на Windows

- **Зупинити**:
  1. У Планувальнику натисніть на завданні правою кнопкою → **«Завершити» (End)**.
  2. Відкрийте **Диспетчер завдань** (`Ctrl+Shift+Esc`) і, якщо там лишився процес **python.exe**, завершіть його.
- **Вимкнути автозапуск**: правою кнопкою на завданні → **«Вимкнути» (Disable)**.
- **Оновити код**:
  1. Зупиніть бота.
  2. Завантажте новий ZIP і розпакуйте його поверх `C:\demo-bot`, **не видаляючи** `.env`, `data` і `logs`.
  3. Виконайте `.\.venv\Scripts\python.exe -m pip install -r requirements.txt`.
  4. Запустіть завдання знову.
- **Де логи**: `C:\demo-bot\logs\bot.log` (робота бота) і `logs\launcher.log` (запуски й перезапуски).

## Деплой на VPS

Для робочого бота клієнта: сервер Ubuntu 24.04 і Docker. Бот працює в контейнері, сам стартує після перезавантаження сервера (`restart: unless-stopped` у `docker-compose.yml`) і перезапускається, якщо впав.

Бот сам звертається до Telegram (polling), тому на сервері не потрібно відкривати жодних портів, окрім SSH.

Мінімальний сервер: 1 vCPU, 1 ГБ RAM, 10 ГБ диска.

### Перше встановлення

Усі команди виконуються на вашому комп'ютері (PowerShell або термінал) чи на сервері — це вказано в кожному кроці.

**1. Підключіться до сервера** (на комп'ютері):

```bash
ssh root@IP_СЕРВЕРА
```

`IP_СЕРВЕРА` і пароль root дає хостинг після покупки VPS. Під час першого підключення на питання про «fingerprint» відповідайте `yes`.

**2. Оновіть систему** (на сервері):

```bash
apt update && apt upgrade -y
```

Завантажуємо список оновлень і встановлюємо їх. Якщо з'явиться рожеве вікно з питанням про перезапуск служб — натисніть Enter.

**3. Увімкніть файрвол** (на сервері):

```bash
ufw allow OpenSSH
ufw enable
```

Перша команда дозволяє SSH — без неї ви відріжете собі доступ до сервера. Друга вмикає файрвол, решта вхідних з'єднань буде заблокована. На питання `Proceed with operation (y|n)?` відповідайте `y`.

**4. Встановіть Docker** (на сервері):

```bash
curl -fsSL https://get.docker.com | sh
```

Офіційний скрипт Docker сам встановить Docker і `docker compose` і налаштує їх запуск разом із сервером.

```bash
docker compose version
```

Перевірка: має вивести версію, наприклад `Docker Compose version v2.x`.

**5. Завантажте код бота** (на сервері).

Репозиторій приватний, тож GitHub попросить логін і токен (не пароль):

1. На GitHub відкрийте **Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token**.
2. Доступ — лише до цього репозиторію, право **Contents: Read-only**.
3. Скопіюйте токен.

Потім на сервері:

```bash
git clone https://github.com/6vkvybwyht-design/demo-bot.git /opt/demo-bot
```

Завантажуємо код у папку `/opt/demo-bot`. На запит `Username` введіть свій логін GitHub, на `Password` вставте токен. Під час вставки символи не відображаються — це нормально.

```bash
cd /opt/demo-bot
git config credential.helper store
```

Переходимо в папку бота. Друга команда запам'ятовує логін і токен для наступних оновлень. Вони зберігаються на сервері у відкритому вигляді, тому токен — лише на читання й лише до цього репозиторію.

**6. Створіть `.env`** (на сервері):

```bash
cp .env.example .env
nano .env
```

Створюємо `.env` із зразка й відкриваємо в редакторі. Заповніть `BOT_TOKEN`, `ADMIN_IDS`, `DEMO_MODE` (див. [«Налаштування»](#налаштування)); `LOG_FILE` лишіть порожнім. Збережіть: `Ctrl+O`, Enter, вийдіть: `Ctrl+X`.

**7. Підготуйте папку для бази** (на сервері):

```bash
mkdir -p data
chown -R 1000:1000 data
```

У папці `data` лежатимуть база й бекапи. Вона розташована на сервері, а не в контейнері, тому дані не зникають під час оновлень. Бот у контейнері працює від користувача з номером 1000 (не root), тому віддаємо папку йому — інакше він не зможе записати базу.

**8. Запустіть бота** (на сервері):

```bash
docker compose up -d --build
```

Docker збере образ бота (перший раз — кілька хвилин) і запустить його у фоні (`-d`). Під час кожного запуску контейнер сам оновлює схему бази (`alembic upgrade head`).

```bash
docker compose ps
docker compose logs -f
```

Перша команда показує стан: має бути `Up`. Друга показує логи в реальному часі — шукайте рядок `Запуск бота`. Вийти з логів: `Ctrl+C`, бот при цьому працює далі.

Перевірте бота в Telegram (`/start`).

### Перенесення бази з ноутбука на сервер

Робіть це, якщо хочете зберегти записи, клієнтів і налаштування, накопичені на ноутбуці.

> ⚠️ Один токен — один запущений бот. Якщо бот з тим самим токеном працює і на ноутбуці, і на сервері, Telegram видаватиме помилку `Conflict: terminated by other getUpdates request`.

1. **Зупиніть бота на ноутбуці.** У Планувальнику завдань завдання бота → **«Завершити»** і **«Вимкнути»**. У Диспетчері завдань переконайтеся, що немає `python.exe` бота.

2. **Зупиніть бота на сервері** (якщо вже запускали):

   ```bash
   cd /opt/demo-bot && docker compose stop
   ```

   Під час копіювання бот не повинен писати в базу.

3. **Скопіюйте базу** — у PowerShell на ноутбуці:

   ```powershell
   scp C:\demo-bot\data\bot.db root@IP_СЕРВЕРА:/opt/demo-bot/data/bot.db
   ```

   `scp` копіює файл через SSH. Він уже є в Windows 10/11.

4. **Поверніть файл боту й запустіть** (на сервері):

   ```bash
   chown 1000:1000 /opt/demo-bot/data/bot.db
   docker compose up -d
   ```

   Перша команда робить скопійований файл доступним боту в контейнері. Під час запуску бот за потреби оновить схему бази.

### Оновлення бота після нових змін

На сервері одним блоком:

```bash
cd /opt/demo-bot
git pull
docker compose up -d --build
docker image prune -f
docker compose logs --tail 30
```

Що робить кожна команда:

1. `cd /opt/demo-bot` — переходимо в папку бота.
2. `git pull` — завантажуємо нові зміни коду з GitHub.
3. `docker compose up -d --build` — перезбираємо образ і перезапускаємо бота. Простій — кілька секунд, база й бекапи в `data` не чіпаються, міграції бази застосовуються автоматично.
4. `docker image prune -f` — видаляємо старі образи, щоб вони не займали диск.
5. `docker compose logs --tail 30` — останні 30 рядків логу: переконайтеся, що є `Запуск бота` і немає помилок.

### Корисні команди на сервері

| Команда | Що робить |
|---|---|
| `docker compose ps` | чи працює бот |
| `docker compose logs -f` | логи в реальному часі (`Ctrl+C` — вийти) |
| `docker compose restart` | перезапустити бота |
| `docker compose stop` / `docker compose up -d` | зупинити / запустити |
| `ls -lh data/backups` | список бекапів |

## Новий клієнт

Як із демо зробити бота для конкретного салону. **Кожен клієнт — окремий бот**:

- свій токен;
- своя папка на сервері;
- своя база.

На одному VPS можна тримати кількох клієнтів у різних папках.

### 1. Створіть бота в Telegram

У [@BotFather](https://t.me/BotFather):

1. Надішліть `/newbot` і задайте назву й username.
2. Збережіть токен.
3. Там само задайте фото (`/setuserpic`) і опис (`/setdescription`) салону.

### 2. Скопіюйте проєкт у нову папку

На сервері:

```bash
git clone https://github.com/6vkvybwyht-design/demo-bot.git /opt/salon-назва
cd /opt/salon-назва
```

Назва папки має бути латиницею, наприклад `/opt/salon-lviv`. Docker використовує її як ім'я проєкту, тож боти різних клієнтів не заважатимуть один одному.

### 3. `config/business.yaml` — дані салону

- `business`: `name`, `address`, `phone`, `map_url` (посилання на Google Maps), `instagram`. Якщо Instagram немає, видаліть рядок.
- `booking.timezone`: часовий пояс, для України `Europe/Kyiv`.
- `booking.slot_step_min`: крок сітки часу, у хвилинах.
- `booking.horizon_days`: на скільки днів наперед можна записатися.
- `booking.min_lead_time_min`: мінімум хвилин від «зараз» до запису.
- `booking.cancel_deadline_hours`: до скількох годин до візиту клієнт може сам скасувати чи перенести запис.
- `reminders`: `before_24h` і `before_2h`, `true` або `false`.

Папка `config` підключена в контейнер окремо (див. `docker-compose.yml`), тому після змін у `business.yaml` достатньо `docker compose restart`, перезбирати образ не потрібно.

### 4. `bot/texts.py` — тексти (за потреби)

Тексти написані для барбершопу, але більшість універсальні. Перегляньте привітання `WELCOME`, а для іншого бізнесу (масаж, автомийка) ще й слова «майстер» і «стрижка» в прикладах.

`texts.py` — частина коду, тому зміни в ньому конфліктуватимуть з оновленнями (`git pull`). Щоб цього уникнути, тримайте зміни клієнта в окремій гілці:

```bash
git checkout -b client/salon-lviv
```

Створюємо гілку клієнта й переходимо в неї. Після правок у `texts.py`:

```bash
git commit -am "Тексти салону"
```

Зберігаємо зміни клієнта в його гілці. Під час оновлення бота замість простого `git pull` виконуйте:

```bash
git pull origin main
```

Ця команда підтягує нові зміни з `main` і поєднує їх зі змінами клієнта.

### 5. `.env` — секрети й режим

```bash
cp .env.example .env
nano .env
```

- `BOT_TOKEN` — токен нового бота;
- `ADMIN_IDS` — Telegram ID власника салону (і ваш, якщо хочете мати доступ до адмінки);
- **`DEMO_MODE=false`** — вимикає кнопку «Подивитись як власник», тестові дані й нічне скидання;
- `DATABASE_URL` — лишіть як є; `LOG_FILE` — порожнім.

### 6. Порожня база й запуск

Виконайте кроки 7–8 з [«Першого встановлення»](#перше-встановлення): `mkdir -p data`, `chown`, `docker compose up -d --build`.

**Не запускайте `seed.demo_data`.** Він заповнює базу вигаданим барбершопом, а без `DEMO_MODE=true` взагалі відмовиться працювати, щоб випадково не стерти дані клієнта.

### 7. Наповнення через адмінку

Власник салону пише боту `/admin` і в адмінці:

1. **💈 Послуги** → «Додати послугу»: назва, тривалість, ціна.
2. **👤 Майстри** → «Додати майстра», потім «Послуги майстра» — позначити, що він робить.
3. **🕐 Графік** — робочі години на кожен день, наприклад `10:00-20:00 14:00-15:00` або `вихідний`.
4. Щоб майстер отримував сповіщення про свої записи:
   1. Майстер сам пише боту `/start` — **без цього Telegram не дозволить боту написати йому першим**.
   2. Майстер дізнається свій ID через @userinfobot.
   3. Власник вписує цей ID у картці майстра → «Telegram ID».

Після цього клієнти можуть записуватися.

## Бекапи

Бот сам робить копію бази SQLite **щодня о 03:30** за часом салону і зберігає **7 останніх** у `data/backups` (файли `bot-РРРР-ММ-ДД_ГГХХСС.db`).

- Копія цілісна, навіть якщо бот саме записує щось у базу.
- Якщо бот був вимкнений о 03:30 (ноутбук вимикали), він зробить копію одразу після запуску, щойно остання копія стане старшою за добу.
- Працює однаково на Windows і на сервері.

**Зробити бекап вручну:**

- Windows: `.\.venv\Scripts\python.exe -m bot.backup`
- сервер: `docker compose exec bot python -m bot.backup`

**Відновити базу з бекапу:**

1. Зупиніть бота (див. вище для Windows; на сервері — `docker compose stop`).
2. Скопіюйте потрібну копію замість бази:
   - на сервері:

     ```bash
     cp data/backups/bot-2026-10-20_033000.db data/bot.db
     chown 1000:1000 data/bot.db
     ```

   - на Windows: скопіюйте файл у Провіднику й перейменуйте його на `bot.db`.
3. Запустіть бота.

**Копія поза сервером.** Бекапи лежать на тому ж диску, що й база: від поломки диска вони не врятують. Раз на тиждень забирайте свіжу копію собі на комп'ютер. У PowerShell на ноутбуці:

```powershell
scp root@IP_СЕРВЕРА:/opt/demo-bot/data/backups/bot-2026-10-20_033000.db .
```

## Розробка

Python 3.12, aiogram 3, SQLAlchemy 2 (async) + SQLite, Alembic, APScheduler, pytest.

```bash
python3.12 -m venv .venv
.venv/bin/pip install -r requirements-dev.txt
.venv/bin/alembic upgrade head
.venv/bin/pytest
```

Структура:

```
bot/
  main.py           — точка входу: python -m bot.main
  config.py         — налаштування з .env і config/business.yaml
  texts.py          — усі тексти
  handlers/         — хендлери (лише приймають дані й викликають services)
  services/         — логіка: слоти, записи, нагадування, адмінка, демо, бекап
  keyboards/, middlewares/, states.py
  db/               — моделі, сесія, сховище стану FSM
config/business.yaml
migrations/         — міграції Alembic
seed/demo_data.py   — демо-дані: python -m seed.demo_data
scripts/run_bot.ps1 — запуск на Windows з автоперезапуском
tests/
```

Повне технічне завдання — `SPEC.md`, правила роботи з репозиторієм — `CLAUDE.md`.

## Подальші покращення

- **Пагінація записів дня в адмінці.** На екрані дня кожен запис — окрема кнопка, а Telegram дозволяє до 100 кнопок у повідомленні. Для демо (до ~33 записів на день) цього достатньо, а для великого салону потрібна розбивка на сторінки, наприклад по 20 записів або по майстрах.
- **Платні доповнення з ТЗ** (розділ 13 `SPEC.md`): онлайн-оплата, бонусна програма, відгуки, розсилки, Google Calendar, статистика, кілька філій, друга мова, Mini App.
- **PostgreSQL для великих клієнтів.** Код написаний під SQLAlchemy, тож перехід зводиться до зміни `DATABASE_URL` і додавання драйвера. Але бекап у `bot/services/backup.py` вміє лише SQLite, тому для PostgreSQL знадобиться `pg_dump`.
